# w2m — Web to Markdown CLI Design

- **Date:** 2026-04-25
- **Author:** procmeans
- **Status:** Approved (brainstorm)
- **Language:** Rust

## 1. Purpose

A command-line tool that downloads a web page (including JavaScript-rendered SPAs such as React / Vue / Next.js sites) and converts the main content into clean Markdown, downloading inline images alongside it.

The project doubles as a Rust learning exercise covering: `clap`, async with `tokio`, HTTP via `reqwest`, headless Chrome control via `chromiumoxide`, HTML parsing with `scraper`, readability-based content extraction, and HTML→Markdown conversion.

## 2. CLI Interface

```
w2m <URL> [OPTIONS]
```

**Arguments**

- `<URL>` — required. The page to convert.

**Options**

| Flag | Default | Description |
|---|---|---|
| `-o, --out <DIR>` | derived from URL | Output directory. Created if missing. Errors if non-empty. |
| `--render` | off | Force headless Chrome rendering, skip the static attempt. |
| `--no-render` | off | Disable headless fallback. Static attempt only. |
| `--selector <CSS>` | none | Override readability with a CSS selector for the main content. |
| `--no-assets` | off | Do not download images. Keep original URLs in Markdown. |
| `--concurrency <N>` | 8 | Parallel image downloads. |
| `-v, -vv` | off | Verbose / very verbose logging. |

`--render` and `--no-render` are mutually exclusive.

**Examples**

```bash
w2m https://example.com/article
w2m https://example.com/article -o ./my-article
w2m https://example.com/spa --render
w2m https://example.com/page --selector "main article"
w2m https://example.com/page --no-assets
```

**Output structure**

```
<out-dir>/
├── index.md
└── assets/
    ├── image-1.png
    └── ...
```

`index.md` begins with frontmatter:

```yaml
---
title: <extracted title>
source_url: <original URL>
fetched_at: <RFC3339 timestamp, UTC>
render_mode: static | headless
---
```

## 3. Architecture

Six modules, each with one responsibility and a clean interface so they can be tested independently.

```
src/
├── main.rs        # entry, install logger, dispatch to pipeline
├── cli.rs         # clap derive structs
├── pipeline.rs    # orchestration
├── fetcher.rs     # static HTTP GET
├── renderer.rs    # headless Chrome
├── extractor.rs   # readability + optional CSS selector
├── converter.rs   # HTML → Markdown + image link rewriting
├── assets.rs      # image download, filename generation
└── output.rs      # write index.md + frontmatter, create dirs
```

### 3.1 Module interfaces

```rust
// fetcher.rs
pub async fn fetch_static(url: &Url) -> Result<String>;  // returns HTML

// renderer.rs
pub async fn render_dynamic(url: &Url, opts: &RenderOpts) -> Result<String>;
//   internal: launch Chrome → goto → wait for networkidle
//             → eval document.documentElement.outerHTML

// extractor.rs
pub fn extract(html: &str, base_url: &Url, selector: Option<&str>) -> Result<Article>;
pub struct Article { pub title: String, pub content_html: String }

// converter.rs
pub fn to_markdown(article: &Article, asset_map: &AssetMap) -> String;

// assets.rs
pub async fn download_all(urls: Vec<Url>, out_dir: &Path, concurrency: usize)
    -> Result<AssetMap>;
//   AssetMap: original URL → local relative path

// output.rs
pub fn write_bundle(dir: &Path, md: &str, meta: &Meta) -> Result<()>;

// pipeline.rs
pub async fn run(url: Url, opts: Opts) -> Result<()>;
```

### 3.2 Why this shape

- `fetcher` and `renderer` both return raw HTML strings. Downstream modules don't care which one produced it.
- `extractor` and `converter` are pure (no IO). They can be unit-tested with HTML fixtures.
- `pipeline` is the only place that wires everything together.

### 3.3 Dependencies

| Purpose | Crate |
|---|---|
| CLI parsing | `clap` (derive feature) |
| Async runtime | `tokio` |
| HTTP client | `reqwest` |
| Headless Chrome | `chromiumoxide` |
| HTML parsing | `scraper` |
| Readability | `readability` |

## 4. Data Flow

```
URL
  │
  ▼
fetcher (unless --render)
  │
  ▼
SPA detection ──── content looks rich ──► extractor
  │
  └── looks like empty SPA shell ──► renderer ──► extractor
                                                     │
                                                     ▼
                                            collect <img> URLs
                                                     │
                                  ┌──────────────────┴──────────────────┐
                                  ▼                                     ▼
                          assets.download_all                  (skip if --no-assets)
                                  │                                     │
                                  └────────► converter (HTML → MD) ◄────┘
                                                     │
                                                     ▼
                                          output.write_bundle
```

### 4.1 SPA detection heuristic

In `pipeline`, after the static fetch:

```rust
fn looks_like_empty_spa(html: &str) -> bool {
    let body_text = extract_body_text(html);
    let text_chars = body_text.chars().filter(|c| !c.is_whitespace()).count();

    // very sparse body
    if text_chars < 200 { return true; }

    // typical SPA mount point + sparse content
    let has_mount = html.contains(r#"id="root""#)
                 || html.contains(r#"id="app""#)
                 || html.contains(r#"id="__next""#);
    if has_mount && text_chars < 500 { return true; }

    false
}
```

Thresholds are empirical — adjust based on real-world usage.

### 4.2 Edge cases

| Case | Behavior |
|---|---|
| Static fetch returns content but readability extracts nothing | Auto-fall back to headless render once. |
| `--no-render` and detected as empty shell | Stop, print warning suggesting `--render`. |
| `--render` and Chrome launch fails | Error, suggest setting `CHROME_PATH`. |
| Single image download fails | Skip, log warning, leave original URL in Markdown, continue. |
| `<img src="data:...">` (base64) | Do not download, keep inline. |
| Same image appears multiple times | Download once, reuse via AssetMap. |

### 4.3 Concurrency

- Image downloads: `tokio::task::JoinSet`, default 8, configurable via `--concurrency`.
- Headless Chrome: a single browser instance per invocation. No pooling.

## 5. Configuration

- Chrome path: auto-detect on macOS (`/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`); override with env var `CHROME_PATH`.
- No config file. All behavior is via flags or env vars.

## 6. Error Handling

```rust
#[derive(Debug, thiserror::Error)]
pub enum W2mError {
    #[error("invalid URL: {0}")]
    InvalidUrl(String),
    #[error("HTTP request failed: {0}")]
    Http(#[from] reqwest::Error),
    #[error("Chrome not found. Set CHROME_PATH or install Chrome/Chromium.")]
    ChromeNotFound,
    #[error("Chrome rendering failed: {0}")]
    Render(String),
    #[error("could not extract main content (try --selector)")]
    ExtractionEmpty,
    #[error("output path already exists and is not empty: {0}")]
    OutputExists(PathBuf),
    #[error("io error: {0}")]
    Io(#[from] std::io::Error),
}
```

**Exit codes**

| Code | Meaning |
|---|---|
| 0 | Success |
| 1 | Generic / argument / IO |
| 2 | Network |
| 3 | Render (Chrome unavailable or failed) |
| 4 | Extraction (no content found) |

**Logging**

- `tracing` only, no `println!` for diagnostics.
- Default level `info`; `-v` → `debug`; `-vv` → `trace`.
- All logs to stderr; stdout reserved for future streaming output mode.

## 7. Testing Strategy

### 7.1 Unit tests (pure functions, no network/browser)

- `extractor::extract` — fixtures in `tests/fixtures/*.html` (real captured pages); assert title and a known excerpt of the content.
- `converter::to_markdown` — given HTML + a stub AssetMap, assert the produced Markdown.
- `pipeline::looks_like_empty_spa` — empty-shell vs rich-page fixtures, assert verdict.
- `assets::guess_filename` — URL → local filename mapping.

### 7.2 Integration tests (mock HTTP, no Chrome)

- `wiremock` to spin up a local mock server.
- End-to-end on the static path: fetch → extract → convert → write bundle. Assert on-disk artifacts.
- Image download: mock server returns a PNG; assert file is written and Markdown link points at it.

### 7.3 Manual smoke tests (real sites)

A short list documented in README. Examples:
- A static blog post (validates the static path).
- A React doc site page, e.g. `react.dev/learn` (validates the SPA path).
- A Next.js page (validates the `__next` heuristic).

Not in CI.

### 7.4 Out of scope

- No mock for `chromiumoxide`; the headless path is covered by the manual list only.
- No coverage targets, no perf benchmarks.

## 8. Out of Scope (this iteration)

- Whole-site recursive crawl (would add concurrency scheduling, dedup, depth limits).
- Authenticated pages (cookies, login flows).
- Robots.txt / rate-limit policies.
- Auto-download / management of Chromium itself.
- Multiple output formats (HTML, JSON, …).

These can become follow-up specs.
